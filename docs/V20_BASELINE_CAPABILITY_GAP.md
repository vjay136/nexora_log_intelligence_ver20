# NLI v18 baseline gap audit for Ver20 NUPIRE

Scope: targeted static audit of `nli-v18` against the attached Ver20 master prompt. This is not a complete repository audit, source-level review of 100 upstream repositories, nor a test run. Conclusions below distinguish existing code from capabilities whose product-level evidence still needs verification.

## Highest-value reusable packages and integration points

- **Runtime path:** `internal/agent` → `internal/multiline` → `internal/engine` → `internal/output`; extend at `engine.Deps` / `V5Parser` seam and keep discovery off the synchronous parse path.
- **Parser runtime:** `internal/registry`, `internal/parsers`, `configs/parsers`, `internal/detector`, `internal/mixedkv`, `internal/drain`, `internal/schema`, `internal/typeinfer`, `internal/timestamp`, `internal/confidence`.
- **Evidence and evolution:** `internal/controlplane/napi_synthesis.go`, `internal/controlplane/assurance*.go`, `internal/progressive`, `parser-policy`; likely add a cohesive NUPIRE/EGPE orchestration package rather than duplicating existing candidate/evaluator pieces.
- **Deployment / rollback:** `internal/controlplane/parser_sync.go`, `internal/familyprofile`, `internal/rollout`, `internal/sync`, `internal/protocol`; bind candidate immutable digest/revision to existing signed artifact and wave rollout mechanisms.
- **Failure and observability:** `internal/quarantine`, `internal/controlplane/quarantine_api.go`, `internal/controlclient`, `internal/output/telemetry.go`, `internal/agent/runtime_telemetry.go`, `internal/controlplane/telemetry_controller.go`, `web`/`internal/webview`.

## Missing or unverified EGPE components

1. A persistent candidate state machine spanning discovery → independent hypotheses → train/held-out split → bounded evaluation → rejection/shadow → approval → signed immutable promotion → drift → rollback, with an auditable decision record.
2. Demonstrated independent candidate generation and held-out evidence isolation. Existing synthesis/tests establish some candidate evaluation, not the complete evolution lifecycle.
3. Production shadow/canary parsing against real flow with measurable parity/error/latency gates, while ensuring candidate work cannot block ingestion.
4. Calibrated confidence and ambiguity handling. Current numeric scores/coverage are evidence heuristics; they should not be represented as calibrated probabilities without calibration data.
5. Explicit limits and outcomes across candidate count, nesting, tokens, fields, regex execution, CPU/time, queue and memory; declarative runtime is a good safety base, but end-to-end bounds require proof.
6. NUPIRE-specific drift metrics, freshness/status, and operator UI wired to real shared backend state.
7. End-to-end NUPIRE release qualification and current v18 comparison evidence.
8. The prompt-mandated repository research/license ledger (100 distinct source-level repositories), absent from this targeted audit evidence.

## Recommended integration shape

Treat ParserPack/registry definitions as the only promotable executable form. Introduce a bounded discovery worker that consumes masked template/unknown summaries plus explicitly governed retained samples, produces declarative hypotheses, and writes candidate/evaluation artifacts to controller storage. Evaluate on disjoint train/held-out records and existing assurance facilities; execute candidates in a restricted declarative runtime. A policy service decides reject, shadow, approval-required, or canary; promotion creates a digest-bound immutable parser revision distributed through existing signed parser sync/rollout. Feed outcomes into current telemetry and quarantine/replay APIs. Keep v18 parsing as fallback and preserve original raw/hash and explicit unknown/quarantine outcomes.

## Highest-value test plan

1. **Baseline/regression:** run `go test ./...`, existing release/web tests, and current `cmd/nli-throughput` smoke; save exact v18 revision, commands, duration and artifacts before edits.
2. **Runtime contract:** real input through agent framing → ParserPack/fallback → normalized JSONL or quarantine; assert raw hash/recovery, valid JSON, no silent loss, correct route, checkpoint accounting, multiline truncation handling.
3. **EGPE policy:** train/held-out contamination rejection; overfit and ambiguous candidate rejection; deterministic reproducibility; score threshold boundaries; no auto-promotion from sample count alone.
4. **Safety/limits:** malformed/nested/long/Unicode/escaped records, regex worst cases, candidate/queue saturation, timeouts and worker crash; assert bounded resources and ingestion continues.
5. **Lifecycle:** candidate checksum tampering, authorization/audit, shadow metrics, canary failure auto-rollback, interrupted restart recovery, stale/drifted clients and revision convergence through existing sync/rollout.
6. **UI/API:** authenticated API and websocket state for queued/running/failed/stale/unknown candidates; verify displayed counts and freshness match backend telemetry.
7. **Performance/release:** compare v18/v20 on same fixtures and host, report throughput, latency distribution, memory and parse/quarantine accounting; run RPM install/upgrade/restart/rollback and config migration checks.

Audit limitations: targeted `rg`/file reads only, no tests run, no UI/browser inspection, no GitHub browsing, no license verification, and no deployment/runtime execution. Treat “missing” as absent from reviewed evidence unless specifically called out as a prompt-level requirement.
